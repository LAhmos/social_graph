📊 WHAT IT MEASURES:

For each kernel implementation (ISPC and MT with different thread counts):
  • Total instruction count
  • CPU cycles
  • Cache references
  • Cache misses
  • Instructions Per Cycle (IPC)
  • Execution time

Then calculates:
  • MT/ISPC instruction ratio
  • Average ratios by thread count
  • IPC comparisons
  • Performance per instruction

💡 UNDERSTANDING RESULTS:

Instruction Ratio (MT/ISPC):
  • 1.0x  = Same instructions
  • >1.0x = MT uses MORE instructions (common)
  • <1.0x = MT uses FEWER instructions (rare)

Why MT typically uses more instructions:
  1. Thread synchronization overhead (locks, atomics)
  2. Function call overhead per thread
  3. Thread pool management
  4. Cache coherency operations
  5. No SIMD (scalar vs vector operations)

Example:
  MT-4 ratio = 1.35x
  → MT with 4 threads executes 35% more instructions than ISPC

🐛 TROUBLESHOOTING:

Problem: "perf: Permission denied"
Solution: sudo sysctl -w kernel.perf_event_paranoid=-1

Problem: "perf: command not found"
Solution: sudo apt-get install linux-tools-generic

Problem: Python import errors
Solution: pip install pandas matplotlib

Problem: No data in results
Solution: Check if benchmarks compiled correctly (run 'make' in each dir)
