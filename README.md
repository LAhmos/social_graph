# SocialGraph ISPC Benchmarks

High-performance microservices implementations using Intel ISPC (Implicit SPMD Program Compiler) for SIMD vectorization, with multithreaded and hybrid execution modes.

## Overview

This repository contains optimized implementations of common social network microservices:
- **User Service**: User registration and authentication
- **Post Service**: Post creation and retrieval
- **UserTag Service**: User mention tracking and notifications
- **Text Service**: Text processing with URL shortening
- **UniqueID Service**: Distributed unique ID generation
- **ShortURL Service**: URL shortening and redirection

Each service supports three execution modes:
1. **ISPC**: Single-threaded SIMD vectorization
2. **MT**: Multithreaded execution (pool or spawn modes)
3. **MT+ISPC**: Hybrid multithreaded + SIMD vectorization

## Quick Start

### Prerequisites

- Linux (tested on Ubuntu 20.04+)
- GCC/G++ (C++11 or later)
- Python 3.6+
- Make

### Installation

1. Clone the repository:
```bash
git clone https://github.com/LAhmos/social_graph.git
cd social_graph
```

2. Run the setup script:
```bash
./setup_environment.sh
```

This will:
- Download and install ISPC v1.28.2
- Install Python dependencies (pandas, matplotlib, plotly, etc.)
- Verify build tools (g++, make)
- Create an environment activation script

3. Activate the environment:
```bash
source env_setup.sh
```

### Building and Running

#### Individual Services

Each service can be built and run independently:

```bash
# User Service
cd user
make
./simple ispc create 100          # ISPC mode: create 100 users
./simple mt 4 create pool 100     # MT mode: 4 threads, pool mode
./simple mt_ispc 4 create 100     # MT+ISPC: 4 threads, hybrid mode

# Post Service
cd post
make
./simple ispc create 100          # Create 100 posts
./simple mt 4 lookup pool 100     # Lookup with 4 threads

# UserTag Service
cd userTag
make
./simple ispc insert 50           # Insert 50 user mentions
./simple mt 4 lookup pool 50      # Lookup with 4 threads
```

#### Comprehensive Benchmarks

Run all benchmarks across all services:

```bash
./run_all_benchmarks_with_modes.sh
```

This will:
- Test ISPC, MT (pool/spawn), and MT+ISPC modes
- Use 1, 4, 8, and 16 threads for multithreaded modes
- Run 1000 iterations per configuration
- Generate CSV files with timing, throughput, and energy data
- Create a summary report with speedup and energy comparisons

Results are saved in `benchmark_results_YYYYMMDD_HHMMSS/`

## Execution Modes

### ISPC Mode
- Single-threaded execution with SIMD vectorization
- Uses AVX2 instructions (8-wide vectors)
- Best for compute-bound operations

### MT Mode
- Multithreaded execution without SIMD
- Two scheduling modes:
  - **pool**: Persistent thread pool (lower overhead)
  - **spawn**: Create threads per batch (higher flexibility)
- Per-thread data structures to avoid contention

### MT+ISPC Mode (Hybrid)
- Combines multithreading with SIMD vectorization
- Each thread executes ISPC kernels on its data partition
- Per-thread maps (no merge phase)
- Best overall performance for large batches

## Data Analysis

### Timing Analysis

Generate CDF plots for latency distributions:

## Output Files

Each benchmark run generates:
- `timing_stats_*.csv`: Per-request timing data (queue delay, execution time, latency)
- `throughput_stats_*.csv`: Throughput measurements
- `energy_measurements_*.csv`: Energy consumption data (if RAPL available)
- `energy_summary_*.csv`: Aggregated energy metrics

## Performance Tips

1. **Thread Count**: Use `4` or `8` threads for best balance (matches typical CPU cores)
2. **Batch Size**: Larger batches (100-2000) show better SIMD benefits
3. **Mode Selection**:
   - Small batches (<50): ISPC or MT pool
   - Large batches (>100): MT+ISPC hybrid
   - Write-heavy: MT pool (lower thread creation overhead)

## Troubleshooting

### ISPC not found
```bash
source env_setup.sh
which ispc  # Should show path to ispc binary
```

### Python packages missing
```bash
pip3 install -r requirements.txt
```

### Compilation errors
Ensure you have C++11 support:
```bash
g++ --version  # Should be GCC 5.0 or later
```

### Energy measurements unavailable
RAPL energy counters require permissions:
```bash
sudo chmod -R a+r /sys/class/powercap/intel-rapl/
```
